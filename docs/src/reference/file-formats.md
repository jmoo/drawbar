# File formats

`nord-format` parses and writes the Clavia / Nord keyboard binary formats: the
`CBIN` container — both header generations, each with its checksum — and
per-model entity layouts declared once with `#[bitbody]`. It does no USB, OS, or
I/O beyond `Read`/`Seek`/`Write`.

**Lossless round-trip is the core invariant.** Unknown regions are kept as raw
byte blocks and decoded values are exposed as read-only views over them, so
`parse → write` is byte-identical even where the semantics are incomplete.

**The support map lives in the rustdoc, beside the code it describes.** The
`formats` module docs define the three support tiers — decoded, structurally
decoded, container-verified stub — and each decoded body's struct doc opens with
how far read and write go, what a read validates, and the provenance of its
placements, followed by its generated byte map.

Every `#[bitbody]` also generates a field registry: `fields()` lists every
declared field under a dotted path with its placement, its current value and the
values it accepts, and `set_field(path, value)` writes one back. That is what
`nord program edit --fields` prints and what drawbar's Advanced table shows.
